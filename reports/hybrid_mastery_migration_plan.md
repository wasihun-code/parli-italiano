# Hybrid Mastery Migration Plan

Transitioning a production application with existing user data to a Global Knowledge Graph is a high-risk operation. This plan outlines a safe, phased migration strategy.

## Phase 1: Preparation & Tooling (Factory-Side)
1. **Freeze Factory Generation:** Halt the creation of new scenarios to establish a stable baseline.
2. **Update Linguistic Extractor:** 
   - Refactor `linguistic_extractor.py` to normalize vocabulary strings and generate deterministic IDs (`word_[text]`).
   - Introduce `dictionary_overrides.json` to handle the ~400 unsafe polysemic words (e.g., forcing "piano" to map to `concept_floor_piano` or `concept_slow_piano` based on scenario context).
3. **Generate Global Dictionary:** Run a one-time aggregation script to compile the new `global_dictionary.json` from the 116 scenarios.
4. **Regenerate Curriculum Mapping:** Run the updated `curriculum_designer.py` to rewrite all 116 `mini_lessons.json` files using the new `word_` and `concept_` IDs.

## Phase 2: Application Architecture (Client-Side)
1. **Update Dexie Schema:** 
   - Increment the `SEED_VERSION` in `db.ts`.
   - Add `global_dictionary` and `scenario_vocab_mapping` tables.
   - Remove `scenario_vocabulary`.
2. **Update Corpus Loader:** Refactor `corpusLoader.ts` to parse the new global dictionary and mapping files during the initial seed.
3. **Refactor Stores:** Update `srsStore.ts` and `progressStore.ts` to operate on the new global IDs and computed completion properties.
4. **Refactor Training UI:** Update `VocabularyTrainingScreen.tsx` to dynamically filter out `exerciseIds` that are marked `learned === true` globally.

## Phase 3: User Data Migration
This is the most critical step. We cannot delete existing user progress.

1. **The Migration Script (`migrate_to_v2.ts`):**
   - On app startup, detect if the user's `srsStore` contains legacy `sXX-vYY` IDs.
   - For every legacy ID, use a pre-compiled mapping file (`legacy_to_global_map.json` generated by the factory during Phase 1) to determine its new Global ID.
   - If a Global ID is found, merge the progress. 
   - **Conflict Resolution:** If a user learned "grazie" in Scenario 1 (streak: 3) but failed it in Scenario 2 (streak: 0), take the *maximum* streak (3) to preserve their hard-earned mastery.
   - Save the unified records under the new `word_grazie` keys and purge the legacy `sXX-vYY` keys.

## Phase 4: Validation & Deployment
1. **Run Full Factory Certification:** Ensure `build_and_certify_scenario.py` passes all 116 scenarios against the new bidirectional global coverage audits.
2. **E2E Testing:** Execute Playwright suite to verify that a user can complete a scenario, and that completing "grazie" in Scenario 1 successfully skips it in Scenario 2.
3. **Release:** Deploy the new frontend build containing the `migrate_to_v2.ts` script.
