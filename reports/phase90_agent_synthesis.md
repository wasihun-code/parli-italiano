# Phase 9.0A: Agent Synthesis Report

This report synthesizes the findings of the specialized sub-agents regarding the current state of Parla Italiano and the requirements for Learning System V3.

## Architecture Agent Findings
- The application relies heavily on deterministic JSON artifacts generated by Factory V2.
- The UI layer (`MiniLessonTrainingScreen`, `VocabularyTrainingScreen`, etc.) currently directly imports these files, leading to static, non-adaptive user experiences.
- Hybrid Mastery exists for Vocabulary but is not fully respected by the core Mini Lessons.
- **V3 Requirement:** V3 must be implemented purely as a runtime orchestration layer in React/Zustand that dynamically filters and sorts the JSON arrays before rendering. It must not touch the IndexedDB schemas or JSON files.

## Learning Science Agent Findings
- **Cognitive Overload:** Scenarios dump up to 49 words on learners in a single "Lesson 1" session.
- **The Alphabetical Trap:** Words are introduced A-Z, destroying semantic context and narrative relevance.
- **Production Cliff:** 85% of exercises are passive recognition. Active production (writing, speaking) is almost non-existent.
- **V3 Requirement:** Enforce a strict cognitive curve (`Recognition → Recall → Production`). Re-sort vocabulary presentation to align with the chronology of the conversation rather than the alphabet.

## Curriculum Agent Findings
- The 116 "Gold Standard" scenarios are structurally uniform (6 lessons, ~40 phrases, ~40 sentences, varying vocab).
- The `curriculum_designer.py` script is merely a chunker, dividing the alphabetized lists by 6.
- **V3 Requirement:** The static curriculum files are immutable. The "Curriculum" in V3 becomes a dynamic path generated on the fly, interpreting the static JSON as a raw "database" of available items rather than a strict sequential playlist.

## Audit Agent Findings
- Existing audits (`certify_scenario.py`) mathematically prove bidirectional coverage (all extracted words are taught).
- Modifying the JSON files would break these audits.
- **V3 Requirement:** V3 needs its own suite of runtime-simulation audits (`progression_audit_v3.py`, `production_balance_audit.py`, etc.) to prove that the dynamically generated paths adhere to the pedagogical rules without mutating the source files.

## QA Agent Findings
- The lack of production exercises means a user could "click through" the entire app by guessing multiple-choice answers without actually learning to speak Italian.
- The transition from static flashcards to the branching conversation simulator is abrupt and lacks scaffolding.
- **V3 Requirement:** The introduction of dictation, assembly, and speaking exercises is mandatory. The UI must cleanly handle the transitions between these varied exercise types.

## Conclusion
Learning System V3 is a critical and necessary evolution to transform Parla Italiano from a "Recognition Engine" into a true language acquisition tool. By implementing V3 strictly as a runtime layer, we preserve the hard-won determinism and integrity of the Factory V2 curriculum while completely overhauling the pedagogical experience.
