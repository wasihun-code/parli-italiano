# Learning Model Forensic Report

This document provides a forensic analysis of how Parla Italiano tracks learning progress, focusing on database schemas, progression mechanics, and mastery algorithms.

## Part 1 — Database Analysis

The application uses two primary storage mechanisms: IndexedDB via Dexie (`src/lib/db.ts`) for raw curriculum data, and LocalStorage via Zustand (`src/store/progressStore.ts` and `src/store/srsStore.ts`) for tracking user progress.

### Dexie Tables (Curriculum Data)
*   **`scenarios`**: `(id, category, sort_order)`. Stores high-level scenario metadata.
*   **`scenario_vocabulary`**: `(id, scenario_id, sort_order)`. Stores extracted vocabulary. The `id` is a locally generated string (e.g., `v1`).
*   **`scenario_phrases`**: `(id, scenario_id, sort_order)`. Stores extracted phrases.
*   **`scenario_sentences`**: `(id, scenario_id, sort_order)`. Stores extracted sentences.
*   **`srs_items`**: `(item_id, item_type, scenario_id, foundation_lesson_id, due_at)`. Mirrors the SRS store for potential offline tracking, but primary tracking is in Zustand.

### Zustand Stores (Progress Tracking)
*   **`progressStore`**: Tracks high-level scenario states.
    *   *Schema*: `scenarioProgress: Record<number, ScenarioPhaseProgress>`
    *   *Fields*: `vocabularyCompleted`, `phraseScore`, `phraseCompleted`, `sentenceScore`, `sentenceCompleted`, `conversationUnlocked`, `miniLessonsCompleted`.
*   **`srsStore`**: Tracks item-level Spaced Repetition System (SRS) data.
    *   *Schema*: `items: Record<string, SrsItem>`
    *   *Fields*: `correctStreak`, `attempts`, `correctAttempts`, `learned`, `dueAt`.

## Part 2 — Vocabulary Tracking

1.  **How is a word identified?** By an arbitrary string ID generated by the linguistic extractor during build time (e.g., `v1`, `v105`).
2.  **Is tracking by ID or by text?** Tracking is strictly by the assigned ID (`srsStore.ts: recordAnswer(id, correct)`).
3.  **Is tracking scenario-specific?** Yes. Because the extractor resets its counter for every scenario, IDs like `v1` exist in all 116 scenarios. To prevent collisions, the runtime prepends the scenario ID (e.g., `s22-v1`), making tracking entirely isolated to the scenario.
4.  **Is tracking global?** **No.**
5.  **What fields are updated after a correct answer?** `attempts` (+1), `correctAttempts` (+1), `correctStreak` (+1), `lastReviewedAt` (now), `dueAt` (extended based on streak). If `correctStreak >= 3`, `learned` becomes `true`.
6.  **What fields are updated after a wrong answer?** `attempts` (+1), `correctStreak` (reset to 0), `dueAt` (set to +5 mins), `learned` (set to `false`).

*Example Lifecycle (chiave):* 
User encounters "chiave" (ID `s22-v5`) in the Apartment Key Pickup scenario. They answer correctly 3 times. `srsItems['s22-v5'].learned` becomes `true`. The word is removed from rotation for Scenario 22.

## Part 3 — Phrase Tracking

1.  **Unique?** No. Tracked by scenario-specific ID (e.g., `s22-p1`).
2.  **Scenario-specific?** Yes.
3.  **Global?** No.
4.  **Mastery algorithm?** Phrases do not use the SRS streak system. Instead, `progressStore.ts` tracks a `phraseScore` (0-100). When `phraseScore >= 85`, `phraseCompleted` is marked `true`.

## Part 4 — Sentence Tracking

1.  **Unique?** No. Tracked by scenario-specific ID (e.g., `s22-s1`).
2.  **Scenario-specific?** Yes.
3.  **Global?** No.
4.  **Mastery algorithm?** Identical to phrases, but utilizing `sentenceScore`. Mastery is achieved when `sentenceScore >= 80`, setting `sentenceCompleted` to `true`.

## Part 5 — Mastery Model

For Vocabulary:
1.  **When does learning begin?** When the item is passed into `registerItem` in `srsStore.ts` upon entering a training screen.
2.  **When is an item considered learned?** When `correctStreak >= 3`.
3.  **When is an item considered mastered?** The system uses "learned" and "mastered" interchangeably at the item level. Scenario mastery occurs when vocab, phrases, sentences, and mini-lessons are completed.
4.  **When is it removed from rotation?** `VocabularyTrainingScreen.tsx` calculates the next term by filtering out items where `srsItems[id]?.learned` is true.
5.  **Can it reappear later?** The SRS algorithm sets a `dueAt` date, but the current UI logic bypasses reviews if `learned === true` within the context of a single session.

## Part 6 — Duplicate Analysis

A corpus-wide forensic analysis of all 116 Gold Standard scenarios reveals massive linguistic redundancy:

*   **Total unique vocab words extracted:** 5,294
*   **Total words appearing in multiple scenarios:** 2,808

**Examples:**
*   **"grazie"**: Appears in **119** different places (e.g., `v105` in At the Gym, `v115` in Laundry Machine).
*   **"buongiorno"**: Appears in **97** different places.
*   **"chiave"**: Appears in **10** different places (e.g., `v60` in At the Library, `v30` in Hostel Dorm).

**Consequence:** Because tracking is bound to the scenario-specific ID (`s57-v105`), if a user masters "grazie" in Scenario 57, they will be forced to re-learn "grazie" from scratch when they encounter it in Scenario 58 (`s58-v115`).

## Part 7 — Knowledge Graph Analysis

**Conclusion: The current architecture DOES NOT support Global Knowledge Tracking.**

The system is entirely siloed. Progress is tightly coupled to the artificial JSON structure of individual scenarios rather than the actual Italian language. If a user masters "sì" in Scenario A, Scenario B has absolutely no algorithmic awareness of this achievement because the entity "sì" does not exist globally; only `sA-v1` and `sB-v14` exist.
